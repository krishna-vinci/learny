# M3b Comfort Implementation Plan

**Goal:**
- Drafting (and every other job) never interrupts the learner: they stay where they are, see live progress everywhere, and get told when it's done.
- Reading is comfortable on a phone: adjustable text, full-screen mode, themes.

**Spec:** D27 (background jobs, notifications) and D28 (M3b) in `docs/decisions/LOG.md`, `docs/UI.md`, `docs/ROADMAP.md` (M3b row).

**Already in place:**
- The job runner runs drafts in the background; many jobs can queue per user.
- SSE `{type:"job"}` events reach the browser (`web/src/api/queries.ts:480`), with `result.notePath`, `result.cardPath` and `result.sourceId` (`shared/src/api.ts:86`).
- Push and ntfy notifications for job done/failed exist server-side (M3a T5).
- The dark palette follows `prefers-color-scheme` only (`web/src/index.css:50`); there's no manual theme choice.

**Gap:** `NewChapterSheet` sends the user to `/jobs` after starting (`web/src/components/NewChapterSheet.tsx:52`). There's no global activity indicator, no in-list placeholder, no in-app completion toast, no reading settings, no full screen, and no theme picker.

**Who:** one persistent Sonnet session using the `ui-ux-pro-max` skill. Slices A → B → C are resumed with SendMessage. Only `web/` is touched, and no server changes are needed. If a slice finds it needs a server change, it stops and reports it; the orchestrator assigns it to codex.

If a step does not fit the real code, stop and report the mismatch (file:line, what you saw) instead of improvising.

## Global constraints

- Mobile first (390px) and desktop (1440/1920). Real-click verification (`elementHandle.click()`/`tap()`/`mouse.click`) at both sizes before a slice counts as done.
- base-ui menu items use `onClick`, never `onSelect`. Sheets and dialogs opened from inside the phone drawer portal to `<body>`.
- Per-device preferences go in `localStorage`, wrapped in try/catch, with a working default when storage throws.
- No new dependencies.

## Slice A — Background jobs UX

### A1. Never navigate away after starting a job
- `NewChapterSheet`, the note toolbar's **Make cards**, Library **Add source**, and chat proposal **Run** all stay on the current page after starting.
- Toast: `Drafting "<title>"…` with a **View** action that opens the activity panel.

### A2. Global activity indicator
- Where it lives:
  - phone: in the mobile header, right side
  - desktop: in the sidebar header
- It shows a spinner and a count of the user's queued and running jobs, and is hidden when there are none. Data: `useJobs()` (all sets), which SSE keeps fresh.
- Tapping it opens the **activity panel**: a popover on desktop, a bottom sheet on phone. Per job:
  - kind icon, title, set, status and live `progress` text
  - elapsed time
  - **Cancel** (`POST /api/jobs/:id/cancel`)
  - failed jobs: the error and a **Retry** (re-POST the same kind, set and title where possible, otherwise a link to the Jobs page)
  - a link at the bottom to the full Jobs page

### A3. "Drafting…" placeholders
- For every queued or running `draft-chapter` job in the current set, show a greyed row with a spinner, its title and its progress text:
  - at the end of the sidebar Notes list
  - in the Set home Notes list
- Tapping one opens the activity panel on that job.
- When the job finishes, the placeholder turns into the real note, which the existing `notes(set)` invalidation already handles.

### A4. Completion toasts, app-wide
- Watch job events. On a live transition to `done` or `failed` (once per job id, never for history loaded at startup):

| Job | Toast | Action |
|---|---|---|
| draft-chapter done | `Chapter "X" drafted` | **Open** → `/s/<set>/n/<notePath minus notes/>` |
| make-cards done | `Cards ready for "X"` | **Review** → the card file |
| ingest done | `Source added` | **Open** → `/library/<sourceId>` |
| any failed | `"X" failed: <short error>` | **Details** → activity panel |

- Toasts persist about 8 s, with at most 3 stacked.

### A5. Nudge to turn on notifications
- The first time a job finishes while the tab is hidden (`document.visibilityState`), or after the third completion, show a one-time tip: "Get notified when drafts finish?" with **Enable**, which goes to Settings → Notifications.
- Remember the dismissal in localStorage.

### A6. Tab title badge
- While jobs are running, prefix `document.title` with `(n) `.

**Verify A:**
- Start two chapters back to back from the Set home.
- Both placeholders appear, the indicator shows 2, and you stay on the page.
- Open another note while they run.
- The completion toast's **Open** lands on the new note.
- Cancel one from the panel.
- Use the faux model (`STUDIUM_FAUX=1`) on a test server with a copy of the sample set so drafts finish quickly.

## Slice B — Reading comfort

### B1. Reading settings
An **Aa** button in the note toolbar opens a popover (desktop) or sheet (phone) with:
- **Text size:** 5 steps (15, 16, 17, 19, 21 px base), shown with a live preview
- **Line width:** narrow (60ch), medium (72ch, default), wide (90ch)
- **Typeface:** sans (the current UI font) or serif (a system serif stack: `ui-serif, Georgia, "Iowan Old Style", serif`; no web font download)
- **Line spacing:** compact 1.5, normal 1.7, relaxed 1.9
- **Reset**

Implementation:
- Apply the values as CSS variables (`--reader-font-size`, `--reader-measure`, `--reader-font`, `--reader-leading`) on the reader root.
- `.studium-prose` in `web/src/index.css` uses those variables with the current values as fallbacks.
- Maths (KaTeX), code blocks and tables scale with the text size. Code blocks use a 0.9 ratio.
- Persisted per device.

### B2. Full-screen reading
- A **Full screen** button in the note toolbar; `f` toggles it on desktop.
- Entering it:
  - hides the sidebar, the chat dock and the chat button, and the mobile header
  - centres the note at the chosen width
  - calls `document.documentElement.requestFullscreen()` where supported (desktop, Android); iOS Safari falls back to the CSS-only immersive mode
- Exiting: a small floating **Exit** button that fades in on scroll-up, tap or mouse move, plus `Esc` and the browser's own exit (listen to `fullscreenchange`).
- Selecting text and following links still work.
- While immersive, keep the screen awake with the `navigator.wakeLock` screen lock when available, and release it on exit or tab hide.

### B3. Remember reading position
- Store the scroll position per note in sessionStorage and restore it when returning to that note in the same session. This is small and makes phone reading much nicer.

**Verify B:**
- Phone: change size, width and typeface; maths and code scale.
- Full screen on phone and desktop; exit by button and Esc.
- Leave a note and return to it: the scroll position is restored.

## Slice C — Themes

### C1. Theme modes
- **System** (default), **Light**, **Dark**, **Sepia**, **Black** (true black for OLED phones).
- Restructure `web/src/index.css`:
  - light tokens stay on `:root`
  - `[data-theme="dark"]`, `[data-theme="sepia"]` and `[data-theme="black"]` each define the full token set
  - "System" applies dark tokens via `@media (prefers-color-scheme: dark)` only when `data-theme` is `system` or absent
  - the existing dark values move into `[data-theme="dark"]` unchanged
- Sepia: warm paper background (around `oklch(0.95 0.03 85)`), brown-grey text, readable contrast.
- Black: `#000` background, dimmed borders, same accent.
- All pairs must meet WCAG AA for body text (check with the ui-ux-pro-max skill's guidance).

### C2. Accent colours
- Six accents: blue (default), teal, green, amber, rose, violet.
- `data-accent` on `<html>` overrides `--primary`, `--primary-foreground`, `--ring` and the link colour per theme.

### C3. Where to change it
- A new **Settings → Appearance** section with the theme and accent pickers (swatches, live) and the reading defaults from B1, which share the same storage.
- A quick theme toggle in the sidebar user footer (cycles System / Light / Dark).

### C4. Consistency
- Set `data-theme` before first paint with an inline script in `web/index.html` that reads localStorage, so there's no flash.
- Update `<meta name="theme-color">` to the current background so the phone status bar matches.
- Mermaid diagrams and code highlighting follow the theme: re-render mermaid on change with a dark or default theme, and switch the highlight palette via CSS variables.

**Verify C:**
- Each theme at 390 and 1440: set home, note with maths, code and mermaid, chat, settings, sign-in.
- No flash on reload.
- The status bar colour changes.
- Screenshots of all 5 themes on one note.

## Order and tests

1. A → B → C, each committed separately after the orchestrator reviews it.
2. Each slice: `pnpm --filter @studium/web exec tsc --noEmit`, `rtk proxy pnpm exec biome check <changed files>`, the vitest files near the changes (add small unit tests for the job-transition detector in A4 and the preference store in B1/C), and `pnpm --filter @studium/web build`.
3. Test server: a copy of `examples/sample-set` and a temp `STUDIUM_DATA_DIR`, with `STUDIUM_FAUX=1` on a spare port. Never the live `data/` or port 3000.
4. After merge: `pnpm --filter @studium/web build` in the main checkout (no service restart needed for web-only changes), then Claude checks the live app at 390 and 1440.
