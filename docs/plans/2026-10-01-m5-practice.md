# M5 Practice — Plan (full scope, Claude cloud task)

**This file is the prompt.** It's self-contained, meant for a Claude Code cloud session on `github.com/krishna-vinci/learny` (branch `main`). It covers the whole milestone, server and web.

**Goal:** the app actively checks what the learner knows. It offers:
- **quizzes** (several question types, auto-graded where possible, AI-graded otherwise)
- **teach-back** (the learner explains; an agent grades against the notes and finds gaps)
- **problem sets** with hints and worked solutions

Every result updates a **weak-spots** record per set, and the Today page surfaces what to practise next (D27: weak spots feed Today). No Anki stats (D23).

**Spec:**
- `docs/ROADMAP.md` (M5 row)
- `docs/decisions/LOG.md` D23, D27, D28
- `docs/AGENT_ROLES.md`, `docs/STUDY_TREE.md`, `docs/REVIEW_LOOP.md`
- `skills/quiz-me/SKILL.md` (the existing chat quiz)
- `server/src/agent/builtins/cards.ts` (`recordQuizResultTool` writes `<set>/log/quiz.md` lines: `- <iso> | topic: … | question: … | verdict: right|partial|wrong | gap: …`)

## Fixed decisions (the orchestrator may override in review)

| # | Decision |
|---|---|
| D1 | **Storage per set.** `<set>/practice/` holds `quizzes/<id>.json`, `problems/NN-<note-slug>.md` and `teachback/<id>.md`. Results go in `<set>/log/practice.jsonl` (append-only, one JSON object per attempt), and the existing `log/quiz.md` keeps being written for chat quizzes. `<set>/practice/weak-spots.json` holds the derived state (rebuildable from the logs). Everything is committed. |
| D2 | **Roles:** new `examiner` (generates quizzes and problem sets; reads notes, cards and sources; writes only `<set>/practice/quizzes/` and `<set>/practice/problems/`) and new `grader` (grades free-text answers, teach-backs and problem attempts against the note and sources; writes nothing, returns structured JSON through a builtin tool). Both are added to the Settings role map (`server/src/routes/settings.ts` `FUTURE_ROLE_KEYS` and the role list). Model defaults fall back to `default` as for other roles. |
| D3 | **Question types:** `mcq` (4 options, one correct), `multi` (choose all that apply), `short` (free text, AI-graded), `numeric` (value plus tolerance, auto-graded), `cloze` (one blank, auto-graded with normalized comparison). Each question carries `id`, `type`, `prompt` (markdown and math), `answer` (hidden from the client until submitted), `explanation`, `note` (path), `anchor` (heading or quote), `topic`, `difficulty` 1–3, `src` (citation id, optional). |
| D4 | **Hidden answers:** the server never sends `answer`/`explanation`/`solution` fields to the client before that question or problem is submitted. Grading happens server-side; deterministic types are graded without AI. |
| D5 | **Weak spots:** keyed by `topic` (normalized lowercase and trimmed) plus note path. Each has `strength` (0–1, exponential moving average of scores: right 1, partial 0.5, wrong 0), `attempts`, `lastSeen`, `nextReview` (a simple interval ladder: 1, 2, 4, 8, 16 days that doubles on ≥ 0.8 and resets to 1 on < 0.5) and the latest `gap` text. A topic is **weak** when `strength < 0.6` or `nextReview ≤ today`. |
| D6 | **Today integration:** `GET /api/today` gains per-set `weakTopics` (top 3) and `practiceDue` (count due). "Do next" gains "Practise <topic>" items after reviews and before drafting, linking to `/s/<set>/practice?topic=…`. |
| D7 | **Teach-back rubric** (grader output): `accuracy`, `completeness`, `clarity` (each 0–4); `misconceptions[]` (claim plus correction plus citation); `missing[]` (key ideas from the note not covered); `score` 0–1; a short `feedback` markdown. Weak spots are updated from `missing` and `misconceptions`. |
| D8 | **Problem sets:** 3–8 problems per note, each with `statement`, `hints[]` (revealed one at a time), `answer` (numeric or expression or short), `solution` (a worked markdown solution), difficulty and topic. Numeric answers are auto-checked; others go to the grader. The learner can "Reveal solution", which logs `revealed: true` and counts as a partial at most. |
| D9 | **Chat quizzes still work:** `recordQuizResultTool` (chat `quiz-me`) also appends to `log/practice.jsonl` and updates weak spots, so both paths feed the same state. |

## PR A: server (`claude/m5-practice-server`)

1. **Shared types** (`shared/src/api.ts`):
   - `PracticeQuestion` (client view without answers)
   - `PracticeQuiz`, `PracticeAttemptResult`, `ProblemView`, `TeachBackResult`, `WeakSpot`, `PracticeSummary`
   - new `JobKind`s `make-quiz` and `make-problems`
   - Today additions (D6)
   - zod schemas where the repo keeps them (`shared/src/schemas.ts`)
2. **Practice store** (`server/src/practice/`):
   - read and write quizzes, problems and teach-backs with path confinement (`resolveInRoot`) and the file locks
   - append to `log/practice.jsonl`
   - `weak-spots.ts`: an update function plus a full rebuild from `practice.jsonl` and `log/quiz.md` (D5)
   - unit tests
3. **Roles and skills:**
   - roles `examiner` and `grader` in `server/src/agent/roles.ts`, with git author identities in `server/src/tree/git.ts` (`AUTHOR_ENV` and `mapAuthorName`)
   - skills `skills/make-quiz/`, `skills/make-problems/` and `skills/grade-answer/` (used for short answers, problem attempts and teach-back per D7)
   - each skill says: ground every question in the note, cite, avoid trivia, vary difficulty, and give no answers in the prompt text
   - update `skills/quiz-me/SKILL.md` to mention that results feed weak spots
   - run `node scripts/skill-history.mjs`
4. **Builtin tools:**
   - `add_practice_question` / `add_problem` (examiner; validated per D3/D8; ids generated server-side, e.g. `q-<8hex>`, `p-<8hex>`)
   - `submit_grade` (grader; returns the structured grade the route awaits)
   - follow the `add_card`/`review_card` pattern in `server/src/agent/builtins/cards.ts`, including null/blank tolerance
5. **Jobs:**
   - `make-quiz {set, notes?: string[], topics?: string[], count: 5-20, types?: QuestionType[], difficulty?}` → a quiz file
   - `make-problems {set, note, count: 3-8}` → a problems file
   - registration, validator, log regex, AI gate, `KIND_ICONS` (web)
6. **Routes** (`server/src/routes/practice.ts`, mounted under `/api/sets/:set/practice` in `server/src/app.ts`):
   - `GET /` → `PracticeSummary` (quizzes list, problem sets, weak spots, due count)
   - `GET /quizzes/:id` (no answers)
   - `POST /quizzes/:id/answer {questionId, response}` → the graded result: deterministic now, or the grader run inline for `short` with a 60 s timeout and a job fallback if slower. It appends to the log, updates weak spots, and returns the explanation.
   - `GET /problems/:file` (no answers or solutions)
   - `POST /problems/:file/:id/hint`
   - `POST /problems/:file/:id/attempt {response}`
   - `POST /problems/:file/:id/reveal`
   - `POST /teachback {note, topic?, text (≤ 8000)}` → grader → `TeachBackResult`, saved to `practice/teachback/<id>.md`, log and weak spots
   - `GET /weak-spots`
   - `POST /weak-spots/rebuild`
   - AI-gate every route that runs a model
7. **Today:** extend `server/src/today/build.ts` and `routes/today.ts` per D6, with tests.
8. **Chat quiz path:** D9 in `recordQuizResultTool`.
9. **Tests:**
   - store/weak-spot math
   - deterministic grading (mcq, multi, numeric tolerance, cloze normalization)
   - answers never leak in GET responses (assert on JSON)
   - path confinement
   - jobs with the faux provider
   - grader route with a stubbed grader
   - Today additions
   - the AI gate
   - Commands: `pnpm --filter @studium/server exec vitest run src/practice src/routes/practice.test.ts src/jobs src/today src/agent src/tree`, plus `tsc` for server, shared and web.

## PR B: web (`claude/m5-practice-web`, from PR A's branch)

1. **Practice page** `web/src/pages/PracticePage.tsx`, route `/s/:set/practice` in `web/src/router.tsx`:
   - header with the weak-spots summary: chips for the top weak topics with a strength bar, and a due count
   - three tabs: **Quiz**, **Teach-back**, **Problems**
   - a "Practice" entry in the set sidebar section (`web/src/components/AppSidebar/AppSidebar.tsx`) and on the set home (`web/src/pages/SetHomePage.tsx`)
   - `?topic=` preselects that topic
2. **Quiz tab:**
   - "New quiz" sheet: pick notes and topics (weak topics preselected), count, types and difficulty. It starts `make-quiz` and shows progress (activity UI).
   - Taking a quiz shows one question at a time, with MathJax/KaTeX and markdown via the existing reader `MarkdownView` in compact mode:
     - MCQ radio, multi checkboxes, numeric input with a unit hint, cloze inline input, short textarea
     - submit shows correct/partial/wrong with the explanation and the source link, then **Next**
   - The end screen shows the score, topics to revisit, and **Retry wrong ones**.
   - Past quizzes are listed with scores.
3. **Teach-back tab:**
   - pick a note (default: the most recent or a weak topic's note); an optional topic
   - a large textarea with the prompt "Explain it as if to a friend"
   - submit shows a grading state, then the result: rubric bars, misconceptions (claim, correction, citation link), missing ideas, and feedback
   - **Try again** keeps the text; history lists earlier teach-backs
4. **Problems tab:**
   - generate a set for a note (`make-problems`)
   - problem cards: statement, **Hint** (one at a time), an answer input, **Check**, and **Reveal solution** behind a confirm
   - graded feedback; the solution renders in markdown with maths
5. **Today:** show `weakTopics` and `practiceDue` on the set cards in `web/src/pages/TodayPage.tsx`, plus the new "Practise …" do-next items.
6. **Toasts:** `web/src/components/Activity/JobToasts.tsx` gets "Quiz ready — Start" and "Problems ready — Open".
7. **Accessibility:**
   - keyboard: 1–4 pick MCQ options, Enter submits, N goes to the next question
   - focus management
   - no layout shift on phone when the keyboard opens (sticky submit bar)
8. **Verify** at 390 and 1440 in Light, Dark and Sepia:
   - seeded quiz: every type answered; wrong and partial results update the weak-spot chips after reload
   - teach-back with a stubbed or seeded result
   - problems: hints, check, reveal
   - Today practice items
   - screenshots attached to the PR or described
