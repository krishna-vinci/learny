# M7 — Media and visuals in notes

**Goal:** agents can put figures, web images, YouTube moments, data charts and interactive HTML into notes. Each one plays in the web reader, degrades to a static form in the PDF book, and stays readable as plain files (Obsidian/GitHub).

**Core rule:** every media kind has an **interactive form (web)** and a **static form (book)**. Nothing in a note ever makes the reader or the book compiler fetch from the internet, except a YouTube player the learner explicitly taps.

## Fixed decisions
- **F1 Directive syntax:** remark-directive leaf form, no space before attributes: `::youtube{src="https://youtu.be/<id>" start=843 end=900}`, `::artifact{src="../artifacts/x.html" poster="../artifacts/x.svg" title="…"}`. Invalid attributes → render a plain link (or nothing, with the raw text) and never throw.
- **F2 Paths are relative to the note file**, like every Markdown tool: a note in `<set>/notes/03-svd.md` writes `![…](../assets/fig.svg)`. The web reader resolves the path against the note's path and must stay inside the same set. The book resolves it the same way.
- **F3 Folders:** `<set>/assets/**` (images and agent SVG figures; git-tracked) and `<set>/artifacts/**` (interactive HTML + poster SVGs; git-tracked).
- **F4 Allowed image types:** png, jpg/jpeg, gif, webp (from the internet or agent), svg (**agent-written only**, never downloaded). No avif. Verify Typst 0.15 compiles webp; if not, the book shows the caption for webp.
- **F5 Raw HTML in notes stays blocked** (no rehype-raw). HTML exists only as sandboxed `artifacts/*.html`.
- **F6 Artifact sandbox:** `<iframe sandbox="allow-scripts">` (never `allow-same-origin`), `srcDoc` = fetched HTML with this prepended as the very first thing in the document: `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; font-src data:">`. So an artifact can't fetch, beacon or load anything external.
- **F7 YouTube is click-to-load:** the reader shows the locally stored thumbnail plus a play button; tapping swaps in `https://www.youtube-nocookie.com/embed/<id>?start=…&end=…&autoplay=1` with `referrerPolicy="strict-origin-when-cross-origin"`, `allow="autoplay; encrypted-media; picture-in-picture; fullscreen"`, `allowFullScreen`. A "Watch on YouTube" link (with `&t=`) is always visible under it (owner-disabled embeds, error 153). No request to YouTube before the tap.
- **F8 Credits:** every saved image has a sidecar `assets/<name>.json` `{url, pageUrl?, sourceId?, alt, license?, savedAt}`. Notes still cite with `[^src:…]`.
- **F9 Limits:** downloaded image ≤ 5 MB and ≤ 6000×6000 px (read from the header); per-set `assets/` total ≤ 50 MB (save refuses beyond); artifact HTML ≤ 300 KB; agent SVG ≤ 300 KB.
- **F10 Chat** (`MessageMarkdown.tsx`) renders `::youtube` / `::artifact` as plain links, and images only when they resolve to the same set. No embeds in chat.
- **F11 Cards:** card-writing agents don't use media (the `.apkg` export doesn't pack files). Say so in the cardsmith skill text.

## Phase 1 — Agent SVG figures and local images (reader and book)
1. `server/src/tree/paths.ts`: `isWritableByAgent` also allows `<set>/assets/**` and `<set>/artifacts/**` (same segment rules). Add `paths.test.ts` cases (allowed, `..`, `library`, bad slug).
2. Roles (`server/src/agent/roles.ts`): the drafter's write rule allows `assets/` and `artifacts/` besides `notes/`; the tutor already uses `isWritableByAgent`. `study_create`/`study_edit` accept `.svg` and `.html` there, with the F9 size caps; an `.svg` containing `<script`, `foreignObject`, `on*=` attributes or `href`/`xlink:href` to anything other than `#…`/`data:` is rejected with a clear tool error.
3. `GET /api/sets/:set/asset?path=<path relative to set>` in `server/src/routes/sets.ts`: must be under `assets/` or `artifacts/` and be an allowed image extension (F4); confined by `resolveInRoot`/realpath; MIME from an extension map; ≤ 10 MB; headers `X-Content-Type-Options: nosniff`, `Cache-Control: private, max-age=3600`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`. 404 when missing. Tests: bytes + MIME, rejects `..`, a notes/ path, a bad extension.
4. `GET /:set/file`: for `.html` under `artifacts/` return `{path, raw}` without frontmatter parsing; cap any file read at 1 MB (413).
5. Web: `MarkdownView` gets an optional `notePath` prop (`<set>/notes/…`, passed by `Reader.tsx`). An `img` override resolves relative `src` against the note path → if it lands in the same set's `assets/` or `artifacts/`, use `/api/sets/<set>/asset?path=…`; `https:` stays as is; anything else renders the alt text. `loading="lazy"`, `decoding="async"`, `max-width:100%`, a `<figure>`-like caption from the alt/title. Add the asset route to the PWA runtime cache in `web/vite.config.ts` (same cap/cleanup rules as the notes cache).
6. Book (`server/src/jobs/book-job.ts`, `server/templates/book/callouts.lua`):
   - Before pandoc, collect every image reference in the chapters; copy the ones that resolve (F2) into `<temp>/media/` (only allowed types, only inside the set) and rewrite the src to `media/<file>`.
   - The Lua filter keeps `Image` elements whose src starts with `media/` (with the caption below) and still turns every other image into its caption + "(image: <url>)" as text. Never let pandoc or Typst fetch.
   - Test in `book-job.test.ts` with stubbed `run` (assert the rewritten markdown and copied files); if pandoc/typst exist locally, also one real compile with an SVG and a PNG.

## Phase 2 — Images from the web (Firecrawl-first)
1. **Image list at ingest:** for web sources (Firecrawl and the plain web extractor), before cleaning, collect the Markdown images of the extracted page: `{url (absolute https), alt, nearHeading}` (max 50, skip data:, tracking pixels < 2 KB when the size is known, svg). Write `library/<id>/images.json`. Check `server/src/ingest/library.ts` around the `source.md` write (≈ line 220) for where to add it; no Firecrawl API change needed (its markdown already contains images; confirm with a test fixture).
2. `save_asset` tool (`server/src/agent/builtins/save-asset.ts`, registered like the other builtins; allowed for drafter and tutor): `{set, url, name, alt, sourceId?}` → https only, `assertPublicUrl` + `safeFetch` (redirects re-checked), F9 caps, `content-type: image/*` **and** magic-byte sniff for png/jpg/gif/webp (hand-written, no dependency), header-only dimension read; per-file-locked write to `<set>/assets/<name>.<ext>` with auto-suffix on collision; the F8 sidecar; git-commits like other agent writes. Returns `{path}` (set-relative) plus the exact Markdown to paste: `![alt](../assets/name.ext)`.
3. Tests (stubbed fetch): SSRF block, too big, wrong MIME, MIME/magic mismatch, svg refused, dimension cap, collision suffix, set quota.
4. Agents find images: first `library/<id>/images.json` of the cited source, then the searxng MCP `images` category as a fallback (skill text, Phase 6).

## Phase 3 — YouTube moments
1. Ingest (`server/src/ingest/youtube.ts`): `transcriptToMarkdown` writes `<!-- t:<seconds> -->` at the start of each paragraph (one per paragraph, not per caption line). Also download the thumbnail `https://i.ytimg.com/vi/<id>/hqdefault.jpg` via `safeFetch` into `library/<id>/thumb.jpg` (failure is non-fatal). Update `youtube.test.ts`.
2. Strip `<!-- t: … -->` wherever `<!-- p: … -->` is stripped today (search snippets, splitter, any reader display) — grep for the `p:` anchor regex and extend it.
3. Re-ingest: existing YouTube sources lack markers; add the markers on the library "Refresh/re-ingest" path if one exists, otherwise report it as an open gap (don't build new UI).
4. Citation: `[^src:<id>#t<seconds>]` accepted next to `#p<n>`; the citation popover shows "at 14:03" and a "Watch on YouTube at 14:03" link. Update the citation parser + `Citation.tsx` and tests.
5. Thumbnail route: `GET /api/library/:id/thumb` (same headers as the asset route; 404 when missing).
6. Web: `remarkStudium.ts` handles leaf `youtube` (F1): validate the 11-char id (same regex as `youtubeVideoId()`), `start`/`end` integers ≥ 0 → `div[data-youtube=<id>][data-start][data-end]`; invalid → plain link. `web/src/components/Reader/YouTubeEmbed.tsx` per F7 (16:9, thumbnail from the library thumb route when the video is a library source, otherwise a neutral placeholder; it never hotlinks i.ytimg.com). Bare YouTube URLs stay links (no auto-embed).
7. Book: the `youtube` leaf directive becomes the thumbnail (copied into `media/` when it exists) + caption "Video: <title or URL> at 14:03" + the link. Pandoc can't parse remark directives: preprocess the markdown in `book-job.ts` (a line matching `^::youtube\{…\}$` → a fenced div or image the filter understands). Same mechanism for `::artifact` in Phase 5.
8. Tests in `Reader.test.tsx`: directive → thumbnail button, no iframe before click, iframe src after click has `youtube-nocookie.com`, `start`/`end`; invalid id → link; raw `<iframe>` in a note is still dropped.

## Phase 4 — Data charts (Vega-Lite)
1. Notes write a fenced block ```` ```vega-lite ```` containing a JSON spec with inline `data.values` only.
2. Web: `CodeBlock.tsx` routes `vega-lite` like it routes `mermaid` to a new `VegaLiteBlock.tsx`, lazy-loading `vega`, `vega-lite`, `vega-interpreter` only when such a block exists (same pattern as the KaTeX/Mermaid loaders). Render with the AST interpreter (`ast: true`, `expr: vega-interpreter`), a loader whose `load`/`sanitize` always rejects (no URL data), renderer `svg`, width = container, colours from the theme tokens (read the CSS variables), re-render on theme change. Invalid JSON or spec → show the code block plus a small "Chart couldn't be drawn" note; never throw (wrap in `RenderBoundary`).
3. Book: in `book-job.ts`, before pandoc, replace each `vega-lite` block with `media/chart-N.svg` rendered on the server by `vega`/`vega-lite` (`new View(parse(compile(spec).spec), {renderer: "none", loader: <rejecting>, expr: interpreter}).toSVG()`), light theme. Failure → keep the code block.
4. Tests: web block renders an `<svg>` for a tiny spec (or mock the loader in jsdom if vega needs canvas) and the fallback for bad JSON; server renders a known spec to an SVG string; a spec with `data.url` is refused.
5. Report the gzip size of the new lazy chunk; the initial bundle must not grow.

## Phase 5 — Interactive artifacts (`::artifact`)
1. `remarkStudium.ts`: leaf `artifact` (F1): `src` must resolve (F2) to `<same set>/artifacts/*.html`; `poster` optional to `artifacts/*.svg`; `title` optional → `div[data-artifact][data-artifact-poster][data-artifact-title]`; invalid → nothing but a muted "(interactive figure unavailable)".
2. `web/src/components/Reader/ArtifactBlock.tsx`: shows the poster (via the asset route) or a titled placeholder with a "Run" button; on tap (and only then, so a long note doesn't start ten iframes on a phone) fetch `GET /:set/file?path=…` `.raw`, build `srcDoc` per F6, render `<iframe sandbox="allow-scripts" srcDoc=… referrerPolicy="no-referrer" title=…>` at 16:10 with a "Full screen" toggle (CSS, not the Fullscreen API). Fetch failure → notice + retry. Offline: the file route is already cached when the note was read; if not, say it needs a connection.
3. Book: `::artifact` → poster image (copied to `media/`) + caption "Interactive: <title> — open this chapter in Studium" ; no poster → caption only.
4. Tests: sandbox attribute is exactly `allow-scripts`; srcDoc starts with the F6 meta; no iframe before tap; src validation (other set, `notes/`, `.js`) → unavailable; fetch failure fallback.

## Phase 6 — Skills and docs
1. New default skill `skills/media-authoring/SKILL.md` (register it per the skill-history mechanism: `scripts/skill-history.mjs`, `skills/.defaults-history.json`). Content, short and concrete:
   - **Which visual for which idea:** process/flow → Mermaid; geometry, vectors, labelled structure → SVG figure; numbers/functions/comparisons → Vega-Lite; something the learner should *play with* (a parameter, a step-through) → artifact; a real-world demo or a lecture moment → YouTube; a figure from the source itself → saved image. At most one visual per main idea; none when text is clearer.
   - **SVG figure rules:** `viewBox`, no fixed width, `currentColor` + one accent, ≥ 14px text, no script/foreignObject/external refs, ≤ 300 KB, a caption via alt text, cite the source.
   - **Images:** first the source's `library/<id>/images.json`, else searxng image search; save with `save_asset`, paste the returned Markdown, keep the credit.
   - **YouTube:** only library sources (add the video first so its transcript is ingested); `start` from the `<!-- t: -->` marker you used; cite `[^src:<id>#t<s>]`.
   - **Artifacts:** one self-contained HTML file (inline CSS/JS, no network, no external fonts), ≤ 300 KB, works at 360px wide and with touch, respects `prefers-color-scheme`; always also write a poster SVG of the key frame; embed with `::artifact{…}`.
2. One line each in `note-authoring`, `draft-chapter`, `explain` pointing to `media-authoring`; cardsmith skill gets F11.
3. `study_create`/`study_edit` (or the note save path) return a **warning** (not an error) when a note's `::youtube` id is not a library source or an image/artifact path doesn't exist.
4. Docs: `docs/decisions/LOG.md` new decision "D-next — Media and visuals in notes" (the table below, F1–F11, deferrals); `docs/STUDY_TREE.md` (`assets/`, `artifacts/`, `images.json`, `thumb.jpg`, `t:` markers); `docs/AGENT_ROLES.md` (`save_asset`, write scopes); `docs/UI.md` (embed behaviour).

| Kind | Web | Book |
|---|---|---|
| Mermaid | rendered (exists) | code block (unchanged; mmdc later) |
| SVG figure / saved image | `<img>` via asset route | image |
| Web image not saved (https) | `<img>` | caption + URL text |

| Vega-Lite | lazy SVG chart | server-rendered SVG |
| Artifact | poster → tap → sandboxed iframe | poster + caption |
