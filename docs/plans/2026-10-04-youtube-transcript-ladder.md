# YouTube transcript ladder implementation plan

**Goal:** Obtain transcripts whenever available while always saving an embeddable YouTube source when transcript retrieval fails.

**Spec:** `docs/prompts/youtube-transcript-ladder.md`, plus the owner's matching 2026-10-04 task and acceptance criteria. Those explicit rulings authorize this build; no additional design approval or commits are required.

**Architecture:** One instance-wide YouTube integration service owns engine discovery, verified updates, encrypted credential storage, status, and paced subprocess execution. The existing extractor keeps its module-first path, escalates through anonymous and signed-in yt-dlp, then emits honest metadata and an unreadable embed-only source. Existing ingest jobs, source markdown/frontmatter, Activity, and Settings consume these results.

**Tech stack:** Existing TypeScript, Hono, Node crypto/fs/child_process, React, existing UI kit and Vitest. No dependencies added.

## Fixed contracts and security decisions

1. `extractYoutube(url, options)` remains compatible; extend options with an injected service or typed transcript-engine interface. Thread the same instance from `main` through WorkspaceManager/IngestJobDeps/ExtractOptions and into the extractor, and to top-level admin routes. Avoid process-global mutable credential state.
2. Normalized engine output uses the existing segment shape (offset and duration in seconds, text); title/authors are optional. `transcriptToMarkdown` retains paragraph target and `<!-- t:N -->` behavior. One English original track is preferred, then curated English, then English auto captions; one available original track may be used when English is absent. Strip standalone music/translator-credit artifacts conservatively, without dropping real prose. Never concatenate language variants.
3. Engine discovery: `YTDLP_PATH`, configured data directory `bin/yt-dlp`, PATH. Status reports missing/found, version, supported platform, Node runtime present, update recommendation, cookie state/source/last success. No paths or secrets returned. Environment cookie variable is `YOUTUBE_COOKIES_PATH` (document it). An explicitly configured invalid engine/cookie path degrades to a friendly state; no raw error leaks.
4. Proposed admin API rooted at `/api/admin/youtube`: GET status; POST `/install` and `/update` use the identical verified download; POST `/cookies` uploads multipart `file`; DELETE `/cookies` removes uploaded credentials only. All run behind existing requireAdmin, session auth, and requestGuard. Bound upload body before buffering (1 MiB file plus small multipart overhead), re-check decoded file size and strict Netscape header/row shape. Friendly validation text is exactly the owner's copy. Status objects never include plaintext, ciphertext, cookie values, filesystem paths, stderr, or raw provider messages. Routes return friendly fixed failures.
5. Reuse `deriveKey(instanceSecret, "studium-secrets-v1")` and existing AES-GCM `encryptSecret`/`decryptSecret`. Store ciphertext and nonsecret status atomically in an instance-local integration file under configured data directory, mode 0600. Private parent directory, random exclusive temporary filenames, atomic rename, cleanup on all errors. Environment-provided cookie takes precedence; mark it clearly, do not read/return its contents to clients. Each run copies plaintext to a private mkdtemp directory/file with mode 0600 and removes it in finally; yt-dlp must never receive the master path. Stale transition persists and invokes notifyAdmins once per credential generation; replacement/success resets appropriately. Bot/rate-limit failures alone must not falsely mark credentials expired.
6. Updates only fetch official releases. Latest metadata may use `https://api.github.com/repos/yt-dlp/yt-dlp/releases/latest`; validate tag and use fixed constructed download URLs. Exact allowed hosts: api.github.com, github.com, release-assets.githubusercontent.com, objects.githubusercontent.com. Every redirect must enforce HTTPS, host allowlist and existing public-IP/DNS pinning. Add optional allowed-hosts to safeFetch without weakening its defaults; scoped tests cover redirects escaping allowlist. Select `yt-dlp_linux` for Linux x64, `yt-dlp_linux_aarch64` for Linux arm64, `yt-dlp_macos` for macOS x64/arm64; other hosts show not available. Match exact filename in the same release's `SHA2-256SUMS`, compare SHA256 before chmod/rename/execution. Bounded download/timeouts (binary up to 100 MiB), serialize concurrent install/update. Preserve previous binary on mismatch or failure. Do not execute unverified download. Environment engine override is operator-owned: explain if installed managed engine is shadowed, never claim it became active. Docker pins `2026.08.19`, downloads matching standalone asset and release checksum, verifies before install; Node already available. No binary checked in.
7. Subprocess: execFile/spawn without shell, canonical validated video ID URL only, `--ignore-config`, ignore ambient plugin locations, `--no-playlist`, no video/audio download, `--js-runtimes node`, private run directory, no credentials in environment/logs. Limit stdout/stderr, wall time, and parsed subtitle file size; cancellation kills only the child started. Prefer dump-single-json to inspect tracks and safeFetch the selected json3 subtitle URL with a YouTube-caption host allowlist, or download exactly one json3 track to the private bounded output directory. Do not trust metadata URLs/paths. No remote code/plugin components or custom yt-dlp configuration loaded.
8. Retrieval ladder: module success returns immediately; empty/throw escalates to anonymous yt-dlp if present, then signed-in yt-dlp if credentials exist. A process-wide service queue enforces start spacing of at least 2 seconds; transient failures get at most one retry after at least 5 seconds, abortable. Tests inject time/wait and subprocess fakes. No retries for genuine disabled/no-caption, stale credential, or cancellation outcomes. Recover metadata from safeFetch oEmbed and thumbnail even when all transcript rungs fail. Catch metadata failures too; never invent a title/author. Cancellation still cancels the job.
9. Error taxonomy internally: blocked, no-captions, disabled, unavailable, stale-cookie, extraction-error. Library's generic no-transcript error is insufficient evidence for genuinely absent captions; default ambiguous failures to retryable blocked/unavailable. Genuine track absence after successful metadata extraction may classify no-captions. Never let a later ambiguous failure overwrite explicit disabled/no-caption evidence. Plain warnings exactly as requested; stale and engine-update advice visible in Settings.
10. Embed-only uses existing schema, video type based on validated YouTube URL if parse tier is basic, preserves URL/thumbnail/title/authors, and has zero timestamp markers or fabricated source prose. Mark unreadable in source summary/frontmatter using existing parse_warning; skip Librarian for absent transcript and ensure downstream agents receive explicit unavailable-transcript guidance rather than treating metadata as evidence. Preserve existing transcript parse tier for real transcript. Propagate extraction warning to successful job result/Activity, without losing it to an unrelated summary warning.
11. Retry transcript is an existing ingest job with explicit validated retry-source ID (no new JobKind). Route verifies the source belongs to the authenticated user's workspace and is a blocked/unavailable YouTube source. Replace transcript/source status in place under the existing locks, preserve source ID and set links, never wipe a good transcript on failed retry, do not bypass dedupe accidentally. UI invalidates source and Activity queries and stays on the page.
12. UI: admin-only new Settings `integrations` section with YouTube panel, matching existing phone/desktop patterns and components. Plain basic/improved/improved + signed-in status, Node present, Install/Update, optional cookie numbered steps, throwaway warning, configured/env/stale/last-success states, Replace/Remove, friendly inline errors. Source and Activity blocked warnings show Settings link for admins and ask-your-admin copy for members. Retry button on blocked sources.
